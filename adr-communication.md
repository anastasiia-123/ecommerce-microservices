# Architecture Decision Record (ADR): Міжсервісна комунікація

## Контекст
Для системи E-commerce необхідно реалізувати взаємодію між `Order Service` та `Catalog Service` під час оформлення замовлення, оскільки сервіс замовлень повинен гарантувати актуальність цін та наявність залишків товарів на складі.

## Рішення
Було прийнято рішення використовувати **Синхронну HTTP-комунікацію (Sync HTTP)** за допомогою REST API (`fetch`).

## Обґрунтування (Чому саме Sync)
1. **Строга консистентність даних (Strong Consistency):** Ми не можемо створити замовлення асинхронно, не знаючи, чи є товар на складі. Синхронний запит дає миттєву відповідь (так/ні).
2. **Простота реалізації:** Для даного етапу системи використання HTTP-запитів є швидшим у розробці та налагодженні, ніж розгортання брокерів повідомлень (RabbitMQ/Kafka).

## Наслідки
* **Плюси:** Гарантія того, що замовлення не буде створено на дефіцитний товар.
* **Мінуси:** Тимчасова недоступність `Catalog Service` заблокує роботу `Order Service` (вища зв'язаність сервісів).
